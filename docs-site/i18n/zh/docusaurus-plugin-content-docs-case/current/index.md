# 案例

协议没法靠说话证明自己被采用——只有真的装进程序里才算。这一节放的是把 MSP 节点做进
**真实发布软件**的案例，不是演示。

| 案例 | 什么样的程序 | MSP 给了它什么 |
|---|---|---|
| [NotchPeninsula](notchpeninsula.md) | 一个有可见状态的 Windows 刘海/灵动岛组件 | 一个集成面：别的程序可以问它"在放什么"、控制播放、弹一条通知——**没有人为此写 MCP server** |

## 什么样的案例才算案例

有意思的案例，程序**不是服务器**。组件、编辑器、播放器——它们有一个用户此刻正盯着的状态。
由此有两个推论：

- 程序已经存在，没人会为了你的协议重写它。节点必须是既有能力上的一层薄壳。
- 真正值得调的接口，都是那些依赖**它自己状态**的："在放什么"、"现在弹一条"、"暂停"。
  让模型用自然语言问，拿到的是过时的答案；让节点直接回答，答案是活的。

这正是 MSP 面向的形状，也正是 stdio 传输装不下的形状：进程早就在跑，登录用户是本人，窗口就在屏幕上。

## 想加自己的案例

在这页旁边提一个 PR。只写能核实的东西：

- 它注册的节点 id；
- 它暴露哪些工具、参数是什么；
- 怎么开启，默认开还是关；
- 以及它**不做**什么。

只列优点的页面叫广告，不叫案例。
