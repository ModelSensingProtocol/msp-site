Model Sensing Protocol

Local software should be a neighbour, not a socket. MSP gives every process a lease so its presence is a fact you can read, a way to speak up when something changes, and the ability to serve its peers directly instead of routing every step through a model.

What is MSP?

MSP is a small wire protocol (8 fixed top-level fields, 4-byte length framing) that lets processes on a machine — or across a LAN — discover each other, call each other's tools, and broadcast events. A node announces itself with a lease; a crashed node simply disappears when the lease goes stale. There is no central broker and no configuration file to maintain: presence is observed, not declared.

Presence, not config

A node writes a declaration and renews it. Anything not renewed within 30 s is ignored, so "what is running right now" is a fact you can read at any moment.

Push, not poll

Events happen inside the app, not inside the model's question. Nodes broadcast on a path; subscribers are woken instead of polling for changes.

Peers, not a hub

Nodes can serve each other directly. The agent is one participant in the mesh, not the switchboard every message has to cross.

What can it enable?

Long tasks that finish themselves

Start a download, wait on a completion signal with polling as a fallback, and get called back when it lands — the call blocks briefly, then becomes a card you can walk away from.

Apps that know each other exist

A downloader hands a finished file to an editor without the model relaying the handoff, because both are nodes in the same mesh.

Devices on the same footing

An ESP32 with six tools and a desktop app are the same kind of thing: a node with a manifest.

Attention routing

When something needs a human — approval, a question, a finished job — the network can say so, and the agent decides whether to notify or stay quiet.

Design philosophy

Three sentences. Everything else in the protocol is a consequence of them — and so is every limitation we admit to.

Everything is a node.

A downloader, an editor, an ESP32 with six tools, the agent itself — the same kind of thing: a lease, a manifest, tools, signals. There is no privileged participant and no broker to configure, so two applications can serve each other without asking the model for permission.

Everything is a signal.

One packet shape carries tool calls, results, broadcasts and heartbeats alike. That is why an event can be pushed instead of polled: nothing in the wire format privileges "request". It is also why nothing is retained — a signal that nobody was listening for is gone, and we say so instead of pretending otherwise.

Every layer is extensible.

Eight fixed fields and a four-byte length prefix; discovery, presence, transports, patterns and authorisation all plug in behind that. A small core is the only way a protocol can survive use cases it did not anticipate — including yours.

What the three sentences cost: no retention, no gossip, and trust equal to reachability. That is written down, not discovered later — see the positioning document.

Start building

Run a node that offers a tool

from msp import MSPNode, Preset

node = MSPNode("weather", preset=Preset.LOCAL_TOOL)

@node.tool("get_weather", "Look up the weather")
def get_weather(location: str, days: int = 3) -> dict:
    return {"location": location, "days": days, "temp_c": 21}

node.start()

Discover it and call it

peer = MSPNode("agent", preset=Preset.FULL_PEER)
peer.start()

print(peer.neighbors())        # ['weather']
result = peer.call("weather", "get_weather",
                   {"location": "Hangzhou"})
print(result.unwrap())

Publish a signal — and receive it elsewhere

# provider: declare once, publish whenever something changes
node.declare_signal("weather.updated")
node.publish("weather.updated", {"location": "Hangzhou", "temp_c": 21})

# consumer: subscribe with a path pattern (* = one segment, ** = many)
@peer.on("weather.*")
def on_weather(sig):
    print(sig.path, sig.payload)   # weather.updated {'location': ...}

Signals are fire-and-forget: nothing is retained and a subscriber that was offline missed it. Treat a signal as "something changed" and fetch the state with a tool.
