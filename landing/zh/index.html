Model Sensing Protocol

本地软件应该是一个邻居，而不是一个插座。 MSP 给每个进程一份租约，让「它还在」变成随时可读的事实；让有变化时它自己能开口； 也让节点之间直接互相服务，而不是每一步都绕着模型走一圈。

MSP 是什么？

MSP 是一个很小的线协议（8 个固定顶层字段 + 4 字节长度前缀），让同一台机器——或同一个 局域网——上的进程互相发现、互相调用工具、互相广播事件。节点用租约宣告自己； 进程崩了，租约过期它自己就消失。没有中心 broker，也没有需要维护的配置文件： 存在是观测出来的，不是声明出来的。

存在，不是配置

节点写一份声明并持续续租。超过 30 秒没续租就视为失效，所以「现在有什么在跑」是随时可读的事实。

推送，不是轮询

事件发生在应用里，而不是发生在模型的提问里。节点按路径广播，订阅者被唤醒，而不是反复去问。

对等，不是总机

节点可以直接互相服务。agent 只是网里的一个参与者，不是每条消息都必须经过的总机。

它能带来什么？

会自己完成的长任务

发起一个下载，以完成信号为主、轮询兜底；落地时被回调。调用先短暂阻塞，然后变成一张可以走开的卡片。

应用知道彼此存在

下载器把完成的文件交给编辑器，不需要模型在中间转手——因为两者本来就是同一张网里的节点。

设备与软件同等

一块带六个工具的 ESP32，和一个桌面应用是同一种东西：一个带 manifest 的节点。

注意力路由

需要人时——等确认、在提问、任务完成——网络能说出来，由 agent 决定提醒还是安静。

设计哲学

三句话。协议里的其它一切由它们推出——我们承认的每条局限也是。

万物皆节点。

下载器、编辑器、带六个工具的 ESP32、agent 自己——都是同一种东西：租约、清单、工具、信号。没有特权参与者，也没有要配置的总线，所以两个应用可以直接互相服务，不必向模型请示。

万物皆信号。

一种报文形状同时承载工具调用、结果、广播、心跳。正因为线格式不把「请求」当特权，事件才能推而不必轮询；也正因为如此什么都不留存——没人听的信号就是丢了，我们明说，而不是假装没有。

每层皆可扩展。

8 个固定字段 + 4 字节长度前缀；发现、存在、传输、模式、授权全部挂在后面。小内核是唯一能让协议活过它没预想到的用法的办法——包括你的用法。

三句话的代价：没有留存、没有 gossip、可达即信任。这些是写下来的，不是以后才发现的——见 定位文档.

开始构建

起一个提供工具的节点

from msp import MSPNode, Preset

node = MSPNode("weather", preset=Preset.LOCAL_TOOL)

@node.tool("get_weather", "Look up the weather")
def get_weather(location: str, days: int = 3) -> dict:
    return {"location": location, "days": days, "temp_c": 21}

node.start()

发现它并调用

peer = MSPNode("agent", preset=Preset.FULL_PEER)
peer.start()

print(peer.neighbors())        # ['weather']
result = peer.call("weather", "get_weather",
                   {"location": "Hangzhou"})
print(result.unwrap())

发布一个信号，在别处收到

# provider: declare once, publish whenever something changes
node.declare_signal("weather.updated")
node.publish("weather.updated", {"location": "Hangzhou", "temp_c": 21})

# consumer: subscribe with a path pattern (* = one segment, ** = many)
@peer.on("weather.*")
def on_weather(sig):
    print(sig.path, sig.payload)   # weather.updated {'location': ...}

信号是发完即忘的：没有留存，订阅者离线期间发的那条就永远丢了。把信号当成 「有东西变了」，状态用工具回查。

安装：pip install --pre msp-py · 同一协议也有 TypeScript、C++、.NET 实现。
